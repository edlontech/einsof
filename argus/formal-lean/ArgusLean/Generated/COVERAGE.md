## Why it does not elaborate yet (Phase C entry blockers)

These are upstream Aeneas limitations/bugs and translation defects — NOT fillable by
`-split-files` external models alone, and NOT fixed by `-impl-namespace` (both tried 2026-05-29):

1. **Unsupported control flow (gates `invoke_start`, `sentinel_elevate_taint`):** Aeneas does
   not yet support early/`return` inside (nested) loops. Both actions fall back to `axiom`.
   Resolution requires upstream Aeneas support OR refactoring the Rust transitions to hoist
   returns out of loops (modifies the deployed artifact — a Phase C decision).
2. **BTreeSet `.copied()` iterator → "Internal error, please file an issue" / "Region ids
   should not be visited directly":** triggered by `BTreeSet`/slice `Iter::copied`. Cascades
   into `delegate`/`revoke`/`cascade_revoke` when `-split-files` is used (the committed default
   extraction avoids that cascade). Upstream Aeneas bug.
3. **`&'static [CapKind]` → "There should be no bottoms in the value":** `CapKind::all()`
   returns a static slice of all 17 variants; Aeneas can't translate the static data. Also hits
   `CapKind::as_str` / `Display::fmt` (big `match` over the enum).
4. **Iterator builtin model gaps:** `Iterator::collect` / `Iterator::copied` fields missing in
   the Aeneas Lean library's builtin trait model.
5. **Elaboration-level translation defects:** self-projection `state.KernelState.KernelState` /
   `event.KernelEvent.KernelEvent`, inline `sorry` emitted in struct-field position (parse
   error), a `meta` identifier clashing with the Lean keyword, an unknown
   `Aeneas.Std.core.cmp.PartialEq.Blanket.ne`, and closure `call_once`/`call_mut` type mismatches.
